# Style bible — «Цветочный квартал»

Стиль зафиксирован по ключевому арту `art/style-test/flowershop-keyart.png`.

## Характер

Тёплая полуреалистичная storybook-иллюстрация. Не плоский вектор, не пиксель-арт. Ощущение: позднее послеполуденное солнце, уютный европейский переулок, мягкая тень, много зелени.

## Ракурс и композиция

- 3/4 сверху, изометрия-дружелюбная (для зданий и предметов — изометрия не строгая, а «мягкая»)
- Свет: тёплый, сверху-слева, длинные мягкие тени
- Никаких людей и лиц на поле и в предметах
- Никакого текста, букв, логотипов — надписи только в UI-слоях игры
- Рассыпанные лепестки и мелочи — фирменная деталь, добавлять в фоны

## Два уровня детализации

| Слой | Детализация | Где применять |
|---|---|---|
| **A. Квартал / фоны** | высокая, живописная, как на ключевом арте | стартовый экран, карта квартала, здания, баннеры каталога |
| **B. Предметы на поле** | «иконочная»: та же палитра и свет, но чище силуэт, меньше текстурного шума, один источник света, читается в 128 px | 60+ предметов мерджа, иконки валют, UI |

**Тест читаемости (обязательный, два масштаба):**
1. Отдельный предмет в 96 px на игровом фоне — понятно ли, что это.
2. **Все уровни цепочки подряд в 76 px** — отличается ли каждый уровень от соседа.
   Проверка: `art/style-test/level-readability.png`, инструмент `tools/mock-board.py`.
   Замер насыщенности: если у соседних уровней она отличается меньше чем на 0.1
   и силуэты однотипные — цепочку на доске не разобрать, нужна переделка.

**Правило контраста внутри цепочки.** Каждый уровень должен отличаться от соседнего
**как минимум одним** из: силуэт (пучок / корзина / арка), цвет (кремовый / розовый /
бирюзовый / золотой), читаемый жест (бант, свеча, гирлянда). Цепочка из однотипных
предметов одной гаммы — брак дизайна, а не брак арта: её нельзя исправить рисованием.

## Приёмы удержания консистентности

1. **Передавать ключевой арт как референс** в каждый новый запрос — это главный инструмент, важнее слов.
2. Единый префикс стиля из шаблона выше, менять только `<ПРЕДМЕТ>`.
3. Постобработка всей пачки одной командой ImageMagick: одинаковая насыщенность и контраст — так расхождения между отдельными картинками сглаживаются.
4. Лестницу цепочки собирать как **разные предметы**, а не «тот же цветок крупнее»: 1 бутон → 3 розы в руке → корзина → композиция → свадебный букет. Разные объекты ИИ рисует консистентно, «то же, но больше» — нет.

## Пайплайн обработки

```bash
# один раз: питон-окружение для инструментов
python3 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt

# 1. ужать сырьё до рабочего разрешения (генератор отдаёт ~1264 px, спрайт — 256 px)
.venv/bin/python tools/shrink-raw.py --max 800

# 2. вырезать фон и уложить в спрайт 256x256
.venv/bin/python tools/cutout.py art/raw/*.png --outdir art/sprites

# 3. проверить весь пакет (размер, фон в углах, обрезка краем, пустые спрайты)
.venv/bin/python tools/check-sprites.py

# 4. собрать атлас + манифест (появится на этапе M1)
```

### Грабли, уже пройденные (не повторять)

1. **Заливка фона от углов не достаёт до фона внутри силуэта.** В венке серое кольцо
   в центре, у лукошка просвет под ручкой, у арки — пространство между опорами.
   Решение: запертый фон ищем как отдельные связные компоненты и удаляем по
   **совпадению цвета с фоном рамки** (`--gap-tol`), а не по площади. Порог по площади
   нужен только чтобы не съесть светлую часть предмета.
2. **Глобальное «сделать прозрачным всё похожее на фон» ломает светлые предметы** —
   пробивает дырки в фарфоровой вазе. Поэтому фон берём только связными областями.
3. **Эрозия до масштабирования даёт разную кромку** на сырье разного разрешения.
   Эрозия и растушёвка выполняются после ресайза, в пикселях итогового спрайта.
4. **Без эрозии на 1 px остаётся светлый ореол** от антиалиасинга генератора.
5. **Оценивать ассет только в реальном размере.** Арка казалась «зеркалом» в превью
   150 px, а в увеличении была нормальной шпалерой; и наоборот — серый центр венка
   в мелком превью не был заметен.

### Почему вырезание делает скрипт, а не ImageMagick

Простая заливка фона не различает **внешний фон** и **щели внутри силуэта**
(просвет между стеблями). А глобальное «сделать прозрачным всё похожее на фон»
пробивает дырки в светлых предметах — фарфоровая ваза, кремовая бумага.

`tools/cutout.py` разделяет эти случаи через связные области: внешний фон берётся
заливкой от рамки картинки, а замкнутые области считаются фоном только если они
мелкие (параметр `--gap-max-frac`). Плюс обязательная эрозия альфы на 1 px —
без неё по краю остаётся светлый ореол от антиалиасинга.

## Юридическая заметка

Yandex Games запрещает ИИ в рантайме игры, но разрешает материалы, сгенерированные заранее. Пайплайн легален; проверять надо только то, что ни один ассет не создаётся в момент игры.
